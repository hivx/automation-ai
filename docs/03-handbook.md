# 03 — The engineering handbook

The canonical content lives in `handbook/`:
- `handbook/STD.md` — the full version: 12 areas, codes `STD-<AREA>-n`, the review checklist (10 items) and the acceptance checklist (6 items).
- `handbook/STD-short.md` — the short version, GENERATED by `scripts/gen-handbook-short.py` and preloaded into agents through the `handbook` skill. Do not edit it by hand.
- `handbook/tool-selection.md` — choosing between a hook, a script, a rule, a skill or an agent.
- `handbook/tool-map.md` — job → preferred tool → fallback tool.
- `handbook/who-calls-whom.md` — the call relationships between roles.

## Three enforcement levels
| Level | Who enforces it | Examples |
|---|---|---|
| 3 | The machine blocks | formatter/linter, hooks, `permissions.deny`, CI, branch protection |
| 2 | An agent checks | the reviewer/qa checklists, findings carrying an STD code |
| 1 | Text | CLAUDE.md, rules, handbook |

A level-1 rule violated ≥ 2 times → coach proposes raising its level.

## Twelve areas
`STRUCT` structure · `NAME` naming · `STYLE` style · `DESIGN` design · `TEST` testing · `ERR` error handling · `GIT` git · `CI` continuous integration · `DOC` documentation · `SEC` security · `DEP` dependencies · `OPS` operations.

Invariant principles live in the handbook. Stack-specific details come from the profile slots (`cmd.*`, `structure.*`, `naming.*`, `test.skip_markers`, `protected_paths`, `ci.*`, `deploy.*`); see `docs/04-profile.md`.

## Finding format
`severity | STD code | file:line | description | fix` — list only blockers/majors; minors are folded into one line.

## Extending
**Adding a rule**
1. Open `handbook/STD.md`, go to the right area, take the NEXT free number (do not insert in the middle, do not reuse an old number).
2. Write one line: `code | imperative sentence | level | enforced by | profile slot or —`.
3. Level 3 requires a real hook/script/CI that enforces it; if there is none yet, write level 2 or 1.
4. Run `scripts/gen-handbook-short.py` to regenerate `handbook/STD-short.md`.
5. Run `scripts/validate.sh`: a stale or hand-edited short version FAILS.

**Retiring a rule:** keep the line, add `(deprecated → STD-X-m)`, lower its level to 1.

**Raising a level:** coach proposes it when a level-1 rule has been violated ≥ 2 times (`docs/07-improvement.md`).

Choose the enforcement mechanism with `handbook/tool-selection.md`; the tool for each job with `handbook/tool-map.md`.
