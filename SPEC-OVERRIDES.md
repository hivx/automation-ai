# SPEC overrides

`SPEC.md` is frozen. Decisions that supersede it are appended here, dated and numbered, newest last. Each entry quotes the SPEC line it overrides, states the new rule and the reason. Earlier implementation adjustments (ADJ-01..ADJ-30) live in `docs/00-overview.md`; this file records owner decisions that change the specification itself.

## 1. Language zones (2026-11-10, P9)
- **Overrides** SPEC.md §0: `REPO_LANGUAGE: Vietnamese              # prose of agents, skills, rules, docs, templates, journal. Change to "English" to switch.`
- **New rule — three language zones, by reader:**
  1. *Zone 1, AI-facing, English:* every `agents/*.md` body, `skills/*/SKILL.md` and `references/*`, `handbook/*.md`, `workflows/**`, `templates/project/claude/rules/*`, `templates/project/CLAUDE.md.tmpl`, the repo's own `CLAUDE.md`, `README.md`, `docs/**` (except the historical records `docs/requirements/**` and `docs/acceptance/**`), `evals/**`, script `--help` text, comments and messages.
  2. *Zone 2, owner-facing, Vietnamese:* exactly one file, `GUIDE-VI.md` (name kept in `scripts/vi-guide.conf`). It is the owner's control panel; its section 9 is the log of owner decisions and requests that every session reads. No other Vietnamese prose in the repo, except the allowlist enforced by `scripts/check-lang.py` (`scripts/vi-strings.json`, `templates/artifacts/vi/**`, historical records, CHANGELOG entries up to 0.3.0, and the first line of `README.md` pointing to the guide).
  3. *Zone 3, artifacts produced inside a project:* prose language chosen by the new slot `output_language` in `.team/config.json` (enum `vi` | `en`, default `vi`). Templates come from `templates/artifacts/vi/` (Vietnamese headings/hints) or `templates/artifacts/` (English).
- **Anchors** (machine-read strings listed in `scripts/anchors.txt`: `Approved-by:`, `## Sources`, `## Definition of Done`, `## Assumptions decided by the team`, verdict and status keywords, `STD-*` codes, IDs, branch and commit patterns, intake fields, PR-body headings, JSON keys, file names) never change language in any zone; `scripts/check-lang.py` fails on any translated form.
- **Reason:** Claude reads AI-facing text on every call; Vietnamese with diacritics costs far more tokens than English for the same content (`docs/research/language-switch.md` measures it) and English is the language the reference kits and Claude Code docs use. The owner keeps reading and writing Vietnamese where it matters to him: the control file and the artifacts of his projects.

## 2. Model routing by the shape of the work (2026-11-11)
- **Overrides** SPEC.md §3: `Model routing: strongest model where a mistake is most expensive. haiku for triage/mechanical; sonnet for orchestration, dev, writer, maintainer, devops; opus for analyst, researcher, architect, designer, reviewer, qa, coach.` and the model column of the §3 role table.
- **New rule:** fable for the roles that coordinate many tasks (team-leader, tech-lead); opus for a role that carries out one concrete job alone and whose mistakes are expensive (dev, maintainer, devops, architect, designer, reviewer, qa); sonnet for reading, analysis and documentation (analyst, researcher, coach, writer); haiku for classification and mechanical work. ADJ-10 still applies (designer runs sonnet for size S/M). Never switch model mid-session.
- **Where it lives:** the `model` frontmatter of `agents/*.md` (the value Claude Code applies), the sample `models` in `templates/project/team/config.json`, `docs/02-team.md`, the `make-agent` skill and its agent template.
- **Reason:** the leads hold the whole feature in view and route many tasks, so they get the model best at long multi-task coordination; one-job roles that write code or change the system get opus; analysis and writing are cheap to redo and run on sonnet.

## 3. CLAUDE.md describes the project, and the team keeps it true (2026-11-11)
- **Overrides** SPEC.md §10: `<project>/CLAUDE.md (block between <!-- team:start --> and <!-- team:end -->, ≤ 25 lines, inserted, never overwriting)` and the §12 appendix note `CLAUDE.md ≤ ~60 lines`.
- **New rule:** the project's CLAUDE.md has two team-kept blocks. The project block (`<!-- project:start -->…<!-- project:end -->`, ≤ 150 lines, above the team block) states what the system is, its commands (copied from `cmd.*`), layout, domain terms, conventions and gotchas. The team block (≤ 25 lines) stays as before. The whole file stays ≤ 200 lines. `/team:onboard` writes the project block from the takeover reports; an old CLAUDE.md is adopted into it and the ai-readiness keep / cut / rewrite is applied, with one reason row per cut or corrected line in `onboarding.md`. `/team:asbuilt` (writer) updates it after every feature; `/team:retro` (coach) reports drift under `## CLAUDE.md`. Text outside both blocks is the human's and is never edited. `scripts/check-claude-md.py` is the machine check.
- **Where it lives:** `skills/onboard`, `skills/asbuilt`, `skills/retro`, `skills/takeover`, `agents/writer.md`, `hooks/role-policy.json` (writer may write `CLAUDE.md`), `templates/artifacts/claude-md.md` (+ `vi/`), `templates/project/CLAUDE.md.tmpl`, `templates/artifacts/{asbuilt,retro}.md`.
- **Reason:** the owner found that a CLAUDE.md holding only the team block never described the project and never changed after onboard. Every agent in every session reads CLAUDE.md first, so the project facts belong there and must follow the code; 60 lines cannot hold the commands, layout and traps of a real system, and Claude Code's guidance is to stay under about 200 lines.

## 4. Run independent work at the same time (2026-11-12)
- **Overrides** SPEC.md §8 `.team/config.json` defaults: `limits{max_rework:3, max_attempts:3, max_questions_round:2, max_parallel_dev:2, …}`.
- **New rule:** whenever several calls do not need each other's results, they go out in ONE message so they run at the same time. Build dispatches in rounds: each round carries every dev for a ready task that shares no file with a task in flight, every rework and every review that can start, up to the dev and reviewer headcount; it never waits for a whole wave to be ticked. Independent Explore questions go out together. A request with several independent items becomes one intake per item and runs as one wave. The config template ships `max_parallel_dev: 4` and `headcount` reviewer 4, architect 1, every other role 2. Merges stay serial, two tasks sharing a file never run together, and the stages of one feature stay in order.
- **Where it lives:** `skills/build`, `agents/tech-lead.md`, `agents/team-leader.md`, `skills/intake`, the Explore steps of `skills/{analyze,design,architect,takeover}` and `agents/{analyst,architect,designer}.md`, `handbook/tool-map.md`, `templates/project/team/config.json`, `docs/01-process.md`.
- **Reason:** the owner asked that a request run on many agents at once instead of wasting time. In the first real project 496 of 522 dispatch messages carried a single Agent call, and the 2-dev cap held back plans whose levels were 5–7 tasks wide. Running agents together costs about the same tokens for the same work, but spends them in a shorter time.

## 5. Hooks remind, they do not block (2026-11-13)
- **Overrides** SPEC.md principle P3 ("anything that must not go wrong is blocked by a hook, a permission or a script") for the kit's own hooks, and the "Blocks (exit 2)" behavior of `protect.sh`, `check-git.sh`, `role-policy.sh`, `stop-check.sh`.
- **New rule:** `.team/config.json` key `enforcement`: `"warn"` (default; a missing key means warn) or `"block"`. In warn mode every check still runs and its message reaches Claude (`RULE (reminder, not enforced) …` in additionalContext, or a systemMessage at Stop), but the tool runs and the agent may stop; stop-check skips the lint/test pass. In block mode the hooks exit 2 as before. Skills, agents, the handbook and STD codes are the rules the team follows; a reminder is a rule to keep or to justify in the report. Gates (`team.py`) and Claude Code permissions are unchanged.
- **Where it lives:** `scripts/lib.sh` (`enforcement`, `remind`, `block`), `scripts/teamlib.py` (`enforcement`, `main`), `scripts/stop-check.sh`, `templates/project/team/config.json`, `templates/schemas/config.schema.json`, `docs/06-install.md`, `docs/guides/incidents.md`, `GUIDE-VI.md`.
- **Reason:** the owner asked that hooks block nothing: skills and rules are working rules, and this much blocking leaves nobody able to work (GUIDE-VI.md section 9, 2026-11-13). In the first real project the main session was stopped on read-only commands at least 30 times and could not run the smoke tests the owner asked for.
